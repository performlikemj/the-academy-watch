# Academy Watch iOS story lane

Run from the repository root with `HARNESS_ROOT=~/Projects/harness` exported:

```sh
(cd academy-watch-ios && xcodegen generate)
bash academy-watch-ios/sim/run.sh --no-grade
# A new journey hash earns only its real launch checkpoint on the first run.
# Run again to execute those journeys fully; existing receipts are reused.
bash academy-watch-ios/sim/run.sh --no-grade
bash academy-watch-ios/sim/check-release.sh academy-watch-ios/sim/report/<stamp>
```

The declared release gate is `sim/check-release.sh`; it reads `sim.release_stories`
from `harness.yaml`, checks coverage and strict report integrity, and requires
both incident stories proven on the current app source tree. Publication alone is not a
pass. Commit instrumentation before collecting release evidence. Reports stay
local; reviewed incident evidence is retained in
`ledgers/research/story-map-proof/`. The declared Basecamp drop is informational;
this script does not transfer files or schedule nightlies.

The lane selects only `AcademyWatchUITests/JourneyRunnerUITests/testJourneys`
under `AcademyWatchExperience`. It never selects the live login-email smoke suite.
An empty/missing execution cannot produce the required per-journey attachments.
Run only one simulator job at a time; never kill another session's build.

Role launch arguments seed UserDefaults synchronously before the root view is
created. `-experienceFixture` controls transport independently. Both seams are
DEBUG simulator-only. Unknown modes/routes fail closed before creating a data
task. Fixtures are synthetic and mechanical proof is not production validation.

`stories.json` is the product inventory. The club story taps My club and asserts the Club verification action
on its destination for an account without a claimed club; it does not prove a
verified workspace. Mermaid and Excalidraw maps are generated by
`node "$HARNESS_ROOT/checks/story-map.mjs" generate academy-watch-ios`.

Release binding hashes `harness.yaml` and the effective scheme, UI target,
destination, locale, timezone, appearance, dynamic type and grading mode. The
runner records the original Git revision and app tree. Acceptance allows an
evidence-only HEAD only when its app tree is identical, and rejects dirty source
at capture or acceptance. A compact Git commit/tree certificate in the report
lets a fresh clone verify this link even if the original unpushed source commit
was replaced by the final evidence-bearing commit. No revision is rewritten.

Local upstream candidate (shared harness unchanged): the iOS branch of
`stories-proof.mjs`, `ios-proof-binding.mjs`, digest emission in `run.sh`, and
visible native selection/navigation-chrome checks in the XCTest runner.
