## The situation

Per-player lookups into scout watchlists (digests, "who watches this player", cleanup) filter by
`player_api_id`, but the table's only index is the composite unique that LEADS on `user_account_id`,
so those queries scan. Add a plain index. Two repo rules apply: every migration guards its DDL with
`migrations/_migration_helpers.py` (prod schema drifted out-of-band), and the chain stays linear — the
current Alembic head is `c201` (verified 2026-08-23).

## The job

### 1. Model — `academy-watch-backend/src/models/scout_watchlist.py`

Lines 16-17 are, verbatim:

```python
    # No standalone indexes: the composite unique below leads on
    # user_account_id, which serves every user-scoped query.
```

Replace those two comment lines with:

```python
    # The composite unique below leads on user_account_id (every user-scoped query);
    # ix_scout_watchlist_player serves the per-player lookups (digests, cleanup).
```

Line 26 is, verbatim:

```python
    __table_args__ = (db.UniqueConstraint("user_account_id", "player_api_id", name="uq_scout_watchlist_user_player"),)
```

```python
    __table_args__ = (
        db.UniqueConstraint("user_account_id", "player_api_id", name="uq_scout_watchlist_user_player"),
        db.Index("ix_scout_watchlist_player", "player_api_id"),
    )
```
