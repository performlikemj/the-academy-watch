## The situation

When a scout asks to contact a contracted player whose club is on the platform, the club manager gets an
email with two links — grant and decline — that now point at `/contact/club-consent/<token>` (P0-A1).
That page does not exist yet. It must: load the decision summary (`GET /api/contact/club-consent/<token>`),
show who is asking about whom, let the manager CONFIRM the action the link carries (grant or decline),
submit it (`POST` to the same URL), and show the result. Invalid/expired/used links show a calm message.
The API answers:

- `GET` → `{ "decision": { "action": "grant"|"decline", "contact_request_id": "…", "player_reference":
  "player profile 12345", "program_name": "Club A", "scout": { "name": "…", "organization": "…" },
  "confirmation_required": true } }`; or HTTP 404 `{ "error": "Consent link is invalid or no longer
  available", "code": "invalid_consent_link" }`.
- `POST` → `{ "decision": "granted"|"declined", "contact_request_id": "…" }`; or the same 404.
