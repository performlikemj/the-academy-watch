## The situation

The contact rail is the product's monetizable moment and the web has no way to start one. Each row of
the Scout Desk (`/scout`) now carries `contactable: true|false`. Add an "Introduce" action per
contactable row that opens a dialog: a short message, then send. The server decides the rest. Its
answers you must handle:

- 201 `{ contact_request: {...} }` → success.
- 400 `{ code: "attestation_required", error: "Football approach rules may prohibit contacting a
  contracted player without their club's consent. Confirm that you already have the current club's
  permission before continuing." }` → show a checkbox "I confirm I have the club's permission" and let
  the scout resend with `permission_attestation: true`.
- 403 `{ code: "scout_not_verified" }` → "You need to be a verified scout" + link to `/scout/verification`.
- 403 `{ code: "player_not_claimable" }` → "This player isn't available for contact."
- 409 `{ code: "active_request_exists" }` → "You already have an open request with this player."
- 409 `{ code: "decline_cooldown_active", cooldown_days: N }` → "A recent request was declined — try
  again in N days."
- anything else → the server's `error` text or "Could not send. Try again."

`APIService.request` throws an `Error` with `err.status` (HTTP code) and `err.body` (the JSON) — read
`err.body.code`.
