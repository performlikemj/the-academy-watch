## The situation

Only VERIFIED scouts may introduce themselves to players. iOS has a verification form; the web has
none, so a web scout can never get verified. Build the page: it shows the scout's current verification
(none / pending / approved / rejected / revoked) and, when there is no active one, a form that submits
`{ full_name, organization, role_title, statement, evidence_urls }`. The API:

- `GET /api/scout/verification` → `{ "verification": null | { id, full_name, organization, role_title,
  statement, evidence_urls: [...], status: "pending"|"approved"|"rejected"|"revoked", submitted_at,
  reviewed_at, review_notes, revocation_reason } }`
- `POST /api/scout/verification` → 201 `{ "verification": {...} }`; 400 `{ "error": "…" }` on a bad
  field; 409 `{ "error": "an active scout verification already exists", "verification": {...} }`.
  Server limits: full_name ≤ 200, organization ≤ 200, role_title ≤ 120, statement ≤ 2000, 1–10 evidence
  URLs, each an absolute `https://` URL ≤ 500 chars. Rate limit 3/hour.
