## The situation

The club console remembers match ids in the browser's localStorage and reconstructs the list with one GET per id,
because the backend had no list endpoint. It has one now (`GET /api/club/<id>/matches` → `{ matches: [...], total }`,
newest first, each row shaped like `getClubMatch` minus `roster`). Switch the console to it and delete the
localStorage index entirely, so the history follows the manager to any device.
