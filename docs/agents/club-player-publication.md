# Club-created adult player publication

Read [the C1 API/policy contract](../p2-club-publication.md) before changing this lane.

- Rollout: `CLUB_PLAYER_PUBLICATION_ENABLED` defaults OFF. Preapply `academy-watch-backend/migrations/maintenance/p2c1_preapply.sql` after p2b3 before deploying; upgrade is idempotent. Recipient email is nullable for privacy and `ix_publication_local_player` supports live local-id checks. C2/C4 carry verbatim p2c1 ancestors: post a BUS CONTRACT with the file SHA256 whenever it changes.
- Activation requires the outbox worker and daily `python -m src.jobs.run_publication_retention --limit 100` (bounded batches sufficient for volume), along with the migration. Expired unclaimed invite addresses/tokens and 180-day invited addresses are purged even while dark; withdrawal/revoke purges immediately. Consent evidence remains.
- Private club provenance never changes to community through consent. Invite, recipient self-claim, explicit current-version public consent, club association, independent moderation and current canonical adult eligibility are separate keys. Unknown/year-boundary/contradictory child evidence remains private. Use `public_adult_ids`; preserve N3 narrow evidence and A1 hold rules.
- Review queue only shows claimed, consented, active pending rows. Show club/squad, adulthood and DOB source, masked emails, timestamps and account/email match flags. No exact DOB/raw email in the moderation DTO. Self-invitation approval is blocked server-side and in the UI. Reject remains available after child DOB corrections.
- Feature OFF must preserve main query counts and provider reads. Only enabled negative/local public reads add the publication check. Provider/local bridges are rejected by resolver-backed consent policy; do not hide positive legacy provider surfaces. Admin nullable link-api removes an old club/provider mapping without moving provider claims/content or consent; new links/merges are blocked. The feature gate precedes player auth in the SPA and uses the ordinary unmatched-route behavior (public home/admin dashboard).
- Club-first requests require current publication plus club grant before player inbox/details/export; messages require both keys. Export withholding never narrows erasure. Club thread revoke starts decline cooldown. Publication withdrawal, club revocation and moderation rejection permanently close old threads; fresh consent/re-approval cannot revive them.
- Notifications contain IDs only and recheck eligibility at delivery. Never persist raw invitation tokens. Account deletion removes C1 publication rows before claims plus all owned club-first introductions and descendants, including withheld rows.
- Regression gates: `test_club_player_publication.py`, `test_club_publication_rc1.py`, `test_club_publication_flag_parity.py`, real `test_club_player_publication_postgres.py`, N3 `test_scout_adults_only.py`, browser `club-player-publication.spec.mjs`. The compact leak sweep has seven private states plus a published control across signed/local aliases, query forms and three audiences.
- PostgreSQL tests refuse hosts/databases except localhost/aw_p2_c1. Never point migrations/tests at the shared DB. Compare preapply twice + upgrade schema with direct upgrade; retained consent blocks downgrade. Schema changes need RLS and guarded DDL.
