# Club-created adult player publication

Read [the C1 API/policy contract](../p2-club-publication.md) before changing this lane.

- Rollout: `CLUB_PLAYER_PUBLICATION_ENABLED` defaults OFF. Preapply `academy-watch-backend/migrations/maintenance/p2c1_preapply.sql` after p2b3 before deploying; upgrade is idempotent. Recipient email is nullable for privacy and `ix_publication_local_player` supports live local-id checks. C2/C4 carry verbatim p2c1 ancestors: post a BUS CONTRACT with the file SHA256 whenever it changes.
- Activation requires the outbox worker and daily `python -m src.jobs.run_publication_retention --limit 100` (bounded batches sufficient for volume), along with the migration. Expired unclaimed invite addresses/tokens and 180-day invited addresses are purged even while dark; withdrawal/revoke purges immediately. Consent evidence remains. Old generated club-player follow labels are repaired in the migration and bounded daily job, even while dark; new follows store no names and live list labels are derived from current eligibility. Exports redact unavailable club subjects while committing legacy label repairs.
- Private club provenance never changes to community through consent. Invite, recipient self-claim, explicit current-version public consent, club association, independent moderation and current canonical adult eligibility are separate keys. Unknown/year-boundary/contradictory child evidence remains private. Use `public_adult_ids`; preserve N3 narrow evidence and A1 hold rules.
- Review queue only shows claimed, consented, active pending rows. Show club/squad, adulthood and DOB source, masked emails, timestamps and account/email match flags. No exact DOB/raw email in the moderation DTO. Self-invitation approval is blocked server-side and in the UI. Reject remains available after child DOB corrections. Renewed consent after rejection re-enters the pending queue; the reviewer sees append-only previous decisions/reasons/times. No additional cooldown applies. Retained club-origin and retired C1 claims are excluded from legacy claim list/review/recheck, even while dark.
- Feature OFF must preserve main query counts and provider reads. Only enabled negative/local public reads add the publication check. Provider/local bridges are rejected by resolver-backed consent policy; do not hide positive legacy provider surfaces. Admin nullable link-api removes an old club/provider mapping without moving provider claims/content or consent; new links/merges are blocked. The feature gate precedes player auth in the SPA and uses the ordinary unmatched-route behavior (public home/admin dashboard).
- Club-first requests require current publication plus club grant before player inbox/details/export; messages require both keys. Export withholding never narrows erasure. Club thread revoke starts decline cooldown. Publication withdrawal, club revocation and moderation rejection permanently close old threads; fresh consent/re-approval cannot revive them. Own retained authored messages are exported separately without inaccessible counterpart content. Withdrawal and revocation have explicit confirmation dialogs.
- Recovery: club revocation, or a recipient withdrawal before any consent, allows an expected-version fresh invitation. Retire the old claim with `verification_method=club_vouch_retired`, retaining its local/account keys and closed threads. Snapshot old permission evidence in append-only recovery audit; reset recipient/claim/consent/moderation and require a fresh claim ID, fresh explicit consent and independent review. The partial local-player/account unique index excludes only that retired marker; ordinary legacy claims retain uniqueness. Consent withdrawal alone never authorizes a club to replace a consenting owner. Candidate lists offer only currently invitable identities.
- Response-owned maps batch publication eligibility/evidence and contact projections; preserve claim/program binding before inbox count/LIMIT. Feature reads share in-flight results with 15-second TTL and focus/30-second revalidation.
- Notifications contain IDs only and recheck eligibility at delivery. Never persist raw invitation tokens. Account deletion removes C1 publication rows before claims plus all owned club-first introductions and descendants, including withheld rows.
- Regression gates: `test_club_player_publication.py`, `test_club_publication_rc1.py`, `test_club_publication_rc1v.py`, `test_club_publication_flag_parity.py`, real `test_club_player_publication_postgres.py`, N3 `test_scout_adults_only.py`, browser `club-player-publication.spec.mjs`. C1F3 recovery and rollout contract:
- Publication review only approves pending rows. Existing shadow DOBs that contradict adulthood block approval and remain stored; moderators see a conflict marker without exposing the DOB.
- Club revocation/recovery quarantines showcase bio, photos, reel, affiliations and their approval fields in `retired_club_showcases`. The next claimant starts blank. Only the retired claimant exports their snapshot; no public/new-owner API reads it. Dark retention purges snapshots after 180 days; account erasure removes them.
- Scouts retain only their authored messages on unavailable club-first histories. The player's account identity, counterpart messages and outcomes are withheld before club grant and after unavailability. Own authored messages from otherwise-withheld threads are exported once; ordinary exports retain their shape.
- Both p2c1 migration/preapply set a transaction-local five-second lock timeout before DDL. On contention roll back and retry the entire script before code deploy. Copy the latest migration/preapply CONTRACT from the BUS verbatim into descendant lanes before validation.
