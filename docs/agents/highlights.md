# Two-key highlights (C2)

- `HIGHLIGHTS_ENABLED` defaults OFF. Disabled API rules behave exactly like unrouted paths (including SPA fallback, wrong methods, OPTIONS/Allow and cache headers); the disabled approvals page follows the normal catch-all redirect. No cut jobs or new links while dark. Export, erasure, retention and asset deletion still run.
- **Club key safe default:** only active, claim-verified A2 managers/owners of an approved, operational program may pick, remove, review or preview highlights. Invite-only manager/coach/analyst/viewer grants cannot exercise this key. The stricter boundary is intentional; widening it is a decision for MJ.
- A whole-club role reviews every visible person, including opponents and bystanders. Structured squad kind/age_limit is checked first; U16s/U-16/Under 16s and youth/academy/junior/colts/minis labels also veto publication. An age-group squad without a limit above 18 always stays private. An unknown squad needs a separate explicit senior-squad attestation by verified whole-club staff; it cannot override known youth data.
- The recording date comes from `VideoMatch.match_date`, never the highlight payload. It must be known, not future, and no later than its verified upload (creation time when there is no upload timestamp). Staff attest the date's accuracy. Stored DOB evidence must establish adulthood both now and at that date; a birthday cannot publish childhood footage. This is human review, not age detection or redaction.
- Candidates are existing server-reviewed reel windows with a human-confirmed identity/report. The client cannot invent times. Cuts are <=60 seconds and strictly shorter than the full recording. A match allows 100 **unrevoked** picks, plus 500 new picks per rolling day; removal frees the live cap, and re-picking never inherits player consent.
- A listed club picks; the approved adult **self** claimant independently decides. Guardian, agent and club-official claims cannot approve. C1 club-origin subjects must pass the canonical public-adult helpers after C1 lands; provenance is never rewritten.
- Approval requires a ready standalone preview at the current source version. A queued, failed, stale or removed preview cannot be approved; worker completion never supplies the player key. Decline immediately blocks preview/public reads, fences jobs and queues deletion. Reconsidering requires a new private preview and a fresh decision while the source still exists.
- Every list/grant rechecks both keys, canonical adult/hold/suppression eligibility, current recipient standing, club listing, source and render generations. Request-owned batched evidence covers claims, source rows, complete rosters, DOBs and listing state. No cross-request/worker eligibility cache. At 1/25/100 clips the SQL count is constant; authenticated lists additionally pay their fixed authentication checks. Inbox polling starts at 30 seconds and backs off to five minutes, pausing while hidden.
- Club remove/private, player revoke and dual-auth admin clip takedown authorize without raw storage verification. Club controls remain available for expired recordings and storage outages; candidate selection and club preview still require an intact raw source. An already approved standalone cut may survive ordinary raw expiry.
- Whole-recording reviews and picks belong to the club, rather than their individual staff author. Staff erasure anonymizes picker/reviewer/event actor links and preserves other players' keys; staff suspension alone does not withdraw an institutional attestation. Recipient erasure still removes their highlights/events and queues every durable attempt blob. Losing the last verified manager may independently make a club unlisted; retained consent is preserved. An administrator or another verified manager can explicitly withdraw the clip or recording review.
- Source edits atomically reset consent and fence jobs even while dark. SQL and ORM writers lock match → highlight → job; PostgreSQL deadlock/serialization failures on highlight routes produce 409 retry responses. Reviewer-only anonymization is not a source change. A same-classification/same-source review by a second manager is a no-op. Cascade deletion has a database cleanup backstop.
- Outbox payloads contain only an opaque highlight ID/version; trusted delivery rechecks eligibility. No identity, raw-match capability or storage credential enters notification payloads.

## API

Club: `GET|POST /api/club/<program>/matches/<match>/highlights`, `POST .../highlight-review`, `DELETE .../highlights/<uuid>`. A pick accepts a server candidate's roster/tracklet/start/end and <=160-character title. Review accepts `classification`, `all_visible_people_adults`, and (unknown squad only) `squad_adult_attested`. GET returns existing picks even after raw expiry, plus a specific recording-block reason and no unavailable candidates.

Player: `GET /api/me/highlight-requests?page=1`, `POST .../<uuid>/decision {decision:"approve"|"private",version}`, `/revoke`, `/retry`; recipient-only preview at `.../<uuid>/preview`. Retry from failed/stale restarts private preview preparation, clears approval and advances the optimistic version. All clip/request identifiers are validated before database lookup; malformed/NUL IDs return 400.

Admin: `POST /api/admin/highlights/<uuid>/takedown` requires the existing admin bearer + API key + current account standing. The Safety page has a highlight-flag-gated individual clip control. It never hides other clips, the whole player, or the whole club.

Public: `/api/players/<signed-id>/highlights`, `/api/programs/<slug>/highlights`, `/api/highlights/<uuid>/clip`.

## Clip delivery and revocation bound

The API checks eligibility and the standalone blob's expected ETag, then issues a **302 to a read-only, single-clip SAS lasting at most 60 seconds**. The adapter and route both pin generated `highlights/<clip-uuid>/<attempt-uuid>.mp4` paths. No raw match or container-wide grant is issued, and no clip bytes are downloaded or buffered in the API. Azure handles ranges and slow viewers without occupying Flask threads. Responses use `private, no-store` and `Referrer-Policy: no-referrer`; private blobs are uploaded with `private, no-store` too.

Revocation blocks new grants immediately. A link issued before revocation can start a download until its 60-second expiry; a transfer already underway may finish. Downloaded bytes cannot be recalled. This small, explicit bound avoids slow public viewers occupying the four API threads. No CDN/browser cache is allowed. Configure blob CORS for the approved web origin's authenticated-preview fetch (`GET`/`HEAD`/range headers); never expose upload/container permissions.

## Retention and worker deployment

1. Apply schema-only `p2c2_preapply.sql` after real C1 and before code. It safely reapplies; the graph head is p2c2. Four private tables use RLS. It includes the unknown-senior attestation column, six source guards, match-first invalidation and the additional clip-delete cleanup trigger. Downgrade refuses any retained rows/jobs.
2. Build `Dockerfile.highlights` with `BACKEND_IMAGE=<immutable backend digest>`; only the separate worker installs ffmpeg. Flask never renders. Run `python -m src.workers.highlight_worker --limit 5` (1..20); schedule often enough to drain cuts and deletion work, and **at least daily while the flag is OFF** for retention. Foundation outbox and private storage must also be operational before enabling.
3. The worker scans a bounded number of exhausted leases instead of stopping at one stuck job, queues every last-attempt path for deletion, prioritizes due deletes, and groups cuts by match. A batch reuses one frozen-source download; changing snapshot/ETag replaces it. Ephemeral source disk remains bounded to one <=12GB match plus clip output. Downloads and ffmpeg each have a 300-second budget; output is video-only, metadata-free H264, <=1280px and <=30MB. All I/O occurs after committing DB locks.
4. UUID attempt leases last 900 seconds. Source changes, revoke, decline and erasure fence old attempts. Deletion jobs normally wait 20 minutes, beyond the lease, so a late upload cannot recreate an orphan after cleanup. The asset is inaccessible while waiting. Transient deletion failures retry three times; failed deletions remain actionable rather than losing their path. Monitor/retry them operationally; raw matches never belong in this queue.
5. The flag-independent `sweep_highlights(limit=100)` runs on each worker invocation. **Unanswered private previews expire after 14 days**, and never outlive the raw recording's earlier retention deadline. Reads enforce those deadlines even before the sweep. Declined clips are already stale/deletion-queued. Approved standalone clips are independent of ordinary raw expiry. This follows the explicit C2F1 task's 14-day rule; the conflicting BUS 90-day instruction is awaiting a direct user clarification.
6. A 90-day audit window bounds revoked highlights and their consent events, expired unused footage reviews, and terminal jobs. Sweeps are capped per table and preserve live institutional review evidence and active public cut paths. Forgotten cut-attempt paths are deletion-queued before their job history is removed. Failed deletions remain until resolved. Export and subject erasure cover all new private data even while OFF.

## Validation

`pytest tests/test_highlights.py tests/test_highlights_review.py tests/test_highlights_dark_real_app.py` covers the RC2 probes, current eligibility, retention, staff anonymity, strict keys, blind approval, scoped grants and exact real-app dark routing.

Opt-in PostgreSQL: create a **dedicated scratch database**, then its `c2_checks` schema. Set `C2_POSTGRES_TESTS=1 C2_POSTGRES_URL=postgresql+psycopg://<local-user>@localhost/<scratch-db>` and run `pytest tests/test_highlights_postgres.py tests/test_highlights_review.py`. The fixture creates/drops tables only in that schema; no fixed dropped database name is embedded. Regression coverage uses real source guards/verifier logic, expiry → club removal → all clip surfaces unavailable → worker blob deletion, parent cascades, raw-SQL lock ordering and concurrency.

`E2E_BASE_URL=... C2_SCREENSHOTS=... pnpm exec playwright test e2e/highlights.spec.mjs` covers dark routing, adult decisions, ready-preview requirements, removal/un-attesting after raw expiry, polling backoff and per-clip admin takedown at desktop/mobile widths. Fixtures are synthetic and test-only.
